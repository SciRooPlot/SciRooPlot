SciRooPlot

Plotting with ROOT, for C++ and Python. Publication-ready figures in a few lines, all plots of a project in one place.

Plots from the command line

Each plot of a project is drawn with one command. Tab completes groups and plot names in bash and zsh, and the plot opens in a window. Group and name are regular expressions: one command can pick several plots, and s and a browse through them.

$ plot spectra ptSpectrum
$ plot spectra multiplicity.*
$ plot spectra .+ pdf

How the comparison is kept fair
          
    
            
  • Both sides make the same figure from the same files; the SciRooPlot code shown is the complete definition of the figure.
    • 
            
  • The ROOT macros are written the way a ROOT user would: one output file, one check that the inputs were found, no helper libraries.
    • 
            
  • Lines are counted without empty lines, comments and the frame of the macro function, the same way on both sides.
    • 
            
  • Most of the ROOT lines go into matching the look: margins, pixel text sizes, tick lengths. A group style file can take part of that, but it still has to be written and kept in sync once.
    • 
            
  • The macros are in the repository () and run with root -l -b -q.
    •

This page is for analyses in Python with numpy, pandas or scikit-learn. It shows how to make consistent figures from arrays and DataFrames: first directly from memory, then from result files, which is the recommended setup for a paper or thesis.

This page needs no ROOT knowledge: the code is plain Python, and the few ROOT terms it uses are explained at the end.

2. Results stored in files

    
In memory, the data is made by the same program as the plots, so every change to a plot runs your computation again. For a quick figure that is fine. For a paper, a thesis or a running analysis, split the two:

    
    
      
  • your analysis or notebook writes its results once, as tables or histograms;
    • 
      
  • the plotting program only reads them: changing a title or a colour never runs the analysis again, and plot redraws any figure in a second;
    • 
      
  • the same files feed every plot, every talk and the thesis, and a colleague with the files and your DefinePlots.py gets exactly your figures;
    • 
      
  • big data stays on disk: tables are read when a plot needs them, a selection runs over millions of rows, and many files of one data set are read as one.
    • 
    

    
Storing is one line per result with pandas. SciRooPlot reads CSV and other text tables directly:

    
at the end of your analysis

    
In the plotting program only the data source changes: it now names the folder, and each file is a table in it, called like the file. Curves are selected from the tables when the plot is drawn: Project1D and Filter as before, Scatter for a curve from two columns.

    
DefinePlots.py, reading the files

    
Big tablesMillions of rows are faster from a ROOT file than from a CSV. uproot (pip, no ROOT needed) writes one: f["events"] = df stores the DataFrame as a table (an RNTuple, ROOT's new format for tables), text columns included, and the plotting program reads it under the same name as the CSV. f["sig"] = np.histogram(…) stores a histogram.

    
optional: a ROOT file with uproot

  


  

    
ROOT terms used here

    

      
        
kRed + 1, kAzure + 2ROOT's named colours and their shades; "#d62728" and (0.84, 0.15, 0.16) work everywhere too. See them all.

Colours, lines and markers

    
ROOT names its colours, line styles and markers with constants like kMagenta + 2, kDotted and kFullCircle. Pick one here to see what it looks like and get the line of code for it.

    
Why plus and minus?ROOT's colour wheel has a few base colours, such as kRed and kAzure. Numbers added or subtracted step through shades of it: for the six primaries (kRed, kGreen, kBlue, kYellow, kMagenta, kCyan) plus means darker and minus lighter, so kRed + 1 is a slightly deeper red; for the others the steps move towards the neighbouring hues. Pick by the swatch, not by the sign. Underneath they are plain numbers, kMagenta is 616, so the code also accepts the index.

  

  

    

      

        Colour
        

        

        
This is ROOT's whole colour wheel. Its uneven shape is ROOT's own: the six primary colours go from −10 to +4, the six mixed ones (kOrange … kPink) from −9 to +10, and there are four greys. ROOT's older numbered colours (e.g. 28, a brown) work as numbers too. Any other colour works as "#rrggbb" or as red, green and blue from 0 to 1, (0.12, 0.47, 0.71): pick it with the colour field (most browsers offer a pipette there) or type it into Look up. srp colorwheel shows the wheel as ROOT draws it, naming the colour under the mouse; AddColorOverview with a list of colours draws your own as a plot.

Colour scales and gradients

    
What a palette isA 2D histogram shows its values as colours, read off the colour scale next to the frame. The colours come from a palette: ROOT ships about sixty, SciRooPlot's base plots use kBird. You can also make your own gradient, as a palette or as the colours of several curves.

    

    

    

      

      

      
Drag the handles on the bar: the colours follow each other along the scale, the first at 0, the last at 1, and each one between can move only up to its neighbours. Between two colours the gradient blends linearly.

Layouts

    
Every plot is drawn on a base plot: the template that fixes the size of the picture, the panels, the margins, the text sizes and the line widths. Pick a shipped one, or design your own here and copy the code into your project.

    
Canvas, pads and framesIn ROOT the whole picture is a canvas. It is divided into pads, one per panel; in each pad the frame is the box with the axes, and the margins around it hold the labels and titles. SciRooPlot numbers the pads 1, 2, 3 … row by row, so plot[2] is the second panel; plot[0] means all pads at once. Lengths here are pixels of the PNG; a PDF has the same proportions.

  

  

  

    
One look for all your figures
All shipped base plots share text sizes, tick lengths and line widths, so a single panel and a 3 × 2 grid look alike side by side in a paper. To change them everywhere, give your lengths to every layout you use, under the shipped names: all your plots follow without touching them.

      

    
Change one detail
Everything that should hold for all plots on a layout can be set on the base plot itself, e.g. a logarithmic colour scale, and stored under a new name. Lengths such as text sizes go in as a PanelLayout, for one layout only.

      

      
Pieces of a grid and more details: Reference, Base plots and own layouts.

Draw options

    
An alias like band or points_endcaps means the same look for histograms and graphs. SciRooPlot translates it to the ROOT option of the data type, and converts the data where ROOT has no matching option.

    
What a drawing option isROOT draws the same histogram as markers with error bars, as steps, as a filled area or as a smooth curve, depending on a short option string such as "E1" or "HIST C". The strings differ between  and  and are hard to remember; the aliases are readable names for them.

    
Without any option: data with a fill is drawn as hist (graphs: area), data with markers set or with errors as points, everything else as hist (graphs: line), 2D data as colz.

  

  

    
  

  

  

    
Viewing angles of 3D drawings

    
The lego, surf, triangle and 3D point drawings are seen from the angles of the pad, plot[1].SetView(theta, phi) in degrees: theta is the height of the eye above the x-y plane, phi the rotation around the z axis. ROOT starts from 30° and 30°, the gallery above uses 35° and 225°. Set on plot[0], the angles hold for all pads of the plot.

Installation

    
Pick one of three ways. Each gives you the srp and plot commands, on Linux and macOS.

  

  

    
A
Homebrew
The prebuilt package from the SciRooPlot tap.

    
B
Conda
The conda-forge package, into the active environment.

    
C
From source
Needs  (6.36.04 or newer) and Boost installed already.

  

  

    
In every shellThe last line of each way, source …/env.sh, adds srp, plot and tab completion to the shell. Put it into ~/.bashrc or ~/.zshrc with an absolute path to have them in every new shell.

    
UpdatesLater on, srp update upgrades SciRooPlot in place, whichever way you installed it.

  

  

    
Building ROOT yourself

    
For the installer, ROOT 6.36.04 or newer has to be installed. If your package manager does not provide it, build it from source (this takes a while) and source its thisroot.sh, also in ~/.bashrc or ~/.zshrc: the installer then finds it.

    

    
SciRooPlot and your plotting projects are compiled with the C++ standard ROOT was built with. The two small dependencies fmt and pybind11 are fetched during the installation if they are missing or too old. ./scripts/install.sh --prefix <dir> installs somewhere else than SciRooPlot/install. Building with CMake directly instead of the installer, -DROOT_DIR=$HOME/root/cmake points to ROOT and -DCMAKE_DISABLE_FIND_PACKAGE_fmt=ON uses the fetched fmt even if one is installed.
